# 给 agent 的接入说明

这份文件是给**装载方**（workbuddy 之类的 agent / bot）读的。人类读 `README.md`，
宿主 skill 系统读 `SKILL.md`，你读这份。

---

## 一句话

这是个**纯检索器**：给一行中文话题串，返回微博 / 小红书 / B站 / 微信公众号 / 抖音上
最近 N 天的真实帖子，带发布时间、作者、互动数、原链接。**它不做任何 LLM 调用。**
归纳、拆查询、重排序——全是**你的活**。

## 零 LLM，这是设计不是缺陷

包内**没有任何模型 API 调用**：不连 OpenRouter，不连 OpenAI / Anthropic / Gemini，
不读 `OPENROUTER_API_KEY` 之类的变量。你可以自己验：

```bash
grep -rn "openrouter\|api.openai\|generativelanguage" scripts/ tools/
# 无输出
```

唯一的外部依赖是**数据源服务**（不是模型）。因此：

- **成本恒定且只有一项**：一次默认检索 $0.005~0.015，无模型费。
- **行为可复现**：排序是死公式 `0.45×相关性 + 0.25×新鲜度 + 0.30×互动`，
  同样的输入给同样的顺序，没有温度、没有静默降级。
- **不抢你的额度，也不替你思考**。你本来就是个 LLM——再花一次钱让另一个模型
  替你拆查询和重排，是重复投入。

## 最关键的一条：没有 planner，话题串就是终点

**你输入的那行字，会被原样打进小红书 / 抖音的搜索框。** 中间没有任何改写层——
没有同义词展开，没有子查询拆分，没有查询重写。

所以一行查询串必须是**中国人真会在小红书搜索框里打的那行字**：

| | 写法 | 为什么 |
|---|---|---|
| ✅ | `AI视频生成 提示词` | 短、无标点、一个概念 |
| ✅ | `国产大模型 本地部署` | 同上 |
| ❌ | `AI视频生成、数字人、虚拟主播的最新进展对比` | 捆了四个概念，平台搜索框吐不出东西 |
| ❌ | `latest developments in AI video generation` | 英文串在中文平台召回近乎为零 |
| ❌ | `AI视频生成最新教程推荐` | `最新/教程/推荐` 是停用词，见下 |

**停用词陷阱**：`scripts/lib/relevance.py` 把这些词并进了相关性停用词表——

```
最新  最好  推荐  教程  评测  对比  消息  更新  分享  经验
skill  skills  tool  tools  prompt  plugin
```

它们**会原样发给平台**，但**相关性打分贡献为零**。只靠它们命中的条目会被相关性闸门丢掉。
别把查询预算花在这上面。

### 推论：多角度调研要跑多次

想要覆盖面，**你自己拆**，然后跑 N 次独立的单概念查询：

```python
for q in ["AI视频生成 提示词", "文生视频 工作流", "AI短片 制作"]:
    run(q)          # 各自独立预算、独立缓存、单次失败可重试
merge_and_dedupe()  # 按 url 去重
rerank_with_your_own_model()
```

**优先展开同义词/别名，其次才是多角度拆分。** 中文平台最痛的是一件事多种叫法
（AI视频生成 / AI生成视频 / AIGC视频 / 文生视频 / AI短片），这比多角度拆分值钱得多。

不要试图把多个概念塞进一行——召回集不会变大，只会变空。

## 接入

### 1. 装

自包含目录，无安装脚本、无构建步骤、无第三方 Python 包（纯标准库，3.9+）。
放到宿主能读到的地方即可。

### 2. 配 key

```bash
export L30D_API_KEY=your_key
```

key 从哪来：团队用户向转发层管理员索取（同时会给你一个 `L30D_BASE_URL`，
届时你不需要注册任何账号）；自己装的话见 `README.md` 的「依赖」一节。

```bash
export L30D_BASE_URL=https://…   # 仅团队用户需要；留空则直连默认数据源
```

也可写配置文件（优先级：进程环境 > 项目 `.claude/last30days-cn.env` > 全局
`~/.config/last30days-cn/.env`，后两者权限须 600）。

### 3. 自检

```bash
python3 scripts/last30days.py --diagnose
```

微博 / 小红书 / B站 / 微信 / 抖音 显示 ✅ 即可用。
**知乎 / 头条 / 百度 显示 ❌ 是预期行为**，原因见下面「可用性闸门」。

### 4. 调用

子进程是最省事的接法：

```python
import subprocess, os, json

out = subprocess.run(
    ["python3", "scripts/last30days.py", topic, "--emit", "json"],
    capture_output=True, text=True, timeout=300,
    env={**os.environ, "L30D_API_KEY": key},
)
data = json.loads(out.stdout)
```

`--emit` 选 `json` 拿结构化数据（你自己排序/归纳），选 `compact` 拿精简 Markdown
（直接喂给自己的上下文）。其余：`md` / `html` / `html-path` / `context` / `path`。

常用参数：

```bash
--days 7            # 改时间窗（默认 30）
--search weibo,wechat   # 只跑指定源
--quick / --deep    # 检索深度
--refresh           # 忽略缓存重跑（失败结果也会进缓存，调试必带）
--as-of 2026-05-01  # 以该日为终点回溯，历史回溯用
--save-dir log      # 落盘报告（不走 env，必须命令行显式给）
```

## 输出契约：你必须遵守的五条

这五条不是礼节，是**这个数据源的已知失真**。违反会让你的结论是错的。

1. **只用返回结果里的内容。** 不得编造链接、互动数、日期、平台情绪。
   覆盖稀疏就直说稀疏。

2. **被跳过的源要如实说出来。** 报告里标「源不可用」的平台，不等于该平台没讨论，
   只等于这次没抓。别让读者以为是前者。

3. **微博的互动数恒为 0**——上游解析层没提供，不是真实为零。
   所以：不要按热度排微博的条目，也不要写「某条点赞为零」。

4. **B站 / 小红书上「AI」这类热词，大量是内容生产工具标签而非议题标签**
   （AI 视频、AI 漫剧、教程引流）。做舆情判断时要额外过滤，否则你会把一堆
   卖课引流帖当成「公众在热议 AI」。

5. **单一信源、无交叉印证的说法，标注为未证实。**

## 可用性闸门：为什么三个源默认是 ❌

源没有真实数据路径就**不跑**，而不是退到 Bing 站内搜索兜底。

上游的行为是：知乎 / 头条接口挂掉后去 Bing 搜 `site:zhihu.com xxx`，捞回几条
**没有发布时间的常青词条**（百度百科之类），在报告里挂上「知乎」标题。
那不是该平台的舆情，是噪音——**比空着更误导**。

| 源 | 状态 | 原因 |
|---|---|---|
| 微博 / 小红书 / B站 / 微信 / 抖音 | ✅ 有 数据源 key 即可用 | — |
| 知乎 | ❌ 除非配 `ZHIHU_COOKIE` 或装 Playwright | 数据源 只有分类搜索，无综合搜索 |
| 今日头条 | ❌ 恒不可用 | 数据源只有按 id 取详情，无搜索端点 |
| 百度 | ⚠️ 抓页时灵时不灵 | 常被安全验证拦 |

显式 `--search zhihu` 也照样被拦。确需强跑：`LAST30DAYS_FORCE_SOURCES=1`
（但你多半不想要那个结果）。

python3 tests/test_tikhub_sources.py        # 微博/B站/微信/抖音 解析回归
python3 tests/test_xiaohongshu_tikhub.py    # 小红书链路回归

全量（23 个，全部用 `python3` 直接跑，不需要 pytest）：

```bash
for t in tests/test_*.py; do python3 "$t" >/dev/null 2>&1 \
  && echo "PASS $t" || echo "FAIL $t"; done
```

fixture 是**实测响应裁到 2 条**。为什么必须拿真实结构跑：数据源的 OpenAPI 把
1063 个端点的 200 响应全标成同一个通用 `ResponseModel`，字段没有任何约定。
照文档写解析必错。

## 已知边界

- **响应时间抖动 2s~30s+**（数据源上游，B站见过 34s）。引擎内置 45s 超时 +
  3 次退避重试（超时不计费，重试免费）。**微博是最慢的源**，单页 10~30s，
  引擎对每源有 60s 硬超时，故微博额外压了 40s 翻页预算——宁可少翻一页，
  也不要整源超时归零。
- **所有数据源请求必带 UA**，不带会被数据源前面的 Cloudflare 拦成 `403 error code 1010`。
  自己扩端点时别忘了。
- **失败结果也会进缓存**。调试时不带 `--refresh`，你会一直看到上一次的空结果。
- **一次默认检索约 5~15 次调用**，$0.005~0.015。

## 附带工具

`tools/xhs_note.py` —— 取小红书**单条**笔记的正文、评论、配图，独立于检索引擎。

存在理由：搜索只给标题和摘要，而很多笔记的干货**全在配图里**，正文常只有一句引子。
且**评论区往往比正文有用**——正文是公告搬运，评论里才是真实执行情况。

```bash
python3 tools/xhs_note.py <note_id|分享链接> [--comments 30] [--images]
```
